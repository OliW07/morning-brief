Privacy policy

Effective date: 26 November 2026.

Project and scope

Morning Brief is an independent personal desktop application maintained by the GitHub account OliW07. This policy covers this project's static website and the open-source desktop code in its repository. It does not replace Oura's, Google's, or GitHub's policies.

Oura data accessed

With your consent, the desktop application requests Oura's daily OAuth permission. It reads daily sleep, readiness and activity summaries and detailed sleep sessions. These may include scores, sleep times and stages, sleep efficiency, overnight heart-rate/HRV summaries, steps and activity energy. It does not request your email, personal-profile, or separate heart-rate time-series permissions.

Purpose and data flow

The app uses these records only to display your personal briefing, assess whether today's cloud data is available, and maintain a local cache for offline display. Requests go directly from your computer to Oura's authorization/token and API services over HTTPS. The OAuth callback listens temporarily on 127.0.0.1:8765, on your own computer, and is not a project-operated public server. Each installation registers its own Oura application.

When separately configured, an Android emulator runs the official Oura app to sync the ring. The official app communicates with Oura and may communicate with Google services according to their own terms. This project does not control their data processing. Ring data reaches Oura before Morning Brief retrieves cloud records.

Local storage and security

The desktop app stores OAuth access/refresh tokens, your API application's client ID and secret, cached Oura records, and daily trigger state on your computer. Default locations are ~/.config/morning-brief/ and ~/.local/state/morning-brief/; XDG settings may change these. Files created by its atomic storage helper are owner-readable/writable (0600). Tokens are not encrypted at rest; administrators, malware, backups, or other software with sufficient access may read them. Protect your computer and backups.

The code uses OAuth state verification, PKCE, serialized refresh-token rotation and HTTPS API calls. It does not log OAuth callback query strings. Local diagnostic logs can contain operational details; treat any shared logs as potentially sensitive. No security measure is a guarantee.

Sharing, analytics and advertising

The project does not operate a server that receives your Oura records or credentials. It does not sell health information, include advertising, or include project-operated analytics or tracking SDKs. The desktop code contacts Oura for authorized requests. No health information or account credentials should be submitted to this public website or repository.

This website and GitHub

This static website does not set application cookies, load third-party fonts, embed analytics, or provide a health-data collection form. It is hosted by GitHub Pages. GitHub may process visitor IP addresses and request information for hosting and security under the GitHub Privacy Statement. If you open an issue, GitHub processes your account and submitted content, and the issue is public. Do not post health records, tokens or secrets.

Retention and deletion

The app normally requests the most recent seven days and replaces its local successful-response cache on subsequent successful fetches. If fetching stops, the last cache remains until replaced or deleted. Tokens and setup state remain until you remove them; logs and backups may persist separately.

You can revoke authorization through Oura's connected-application controls and stop the app's automation. To remove Morning Brief's local credentials and cached data, delete its configuration and state directories after stopping its processes. Any separately installed Android emulator stores its own Oura account/app data; remove that app data or emulator separately if desired. Deleting local files does not delete records from Oura's services. Contact Oura for account-level deletion or data-rights requests.

Your choices

Authorization is optional. You can use a clearly labelled sample preview without connecting Oura. You can revoke access, disable scheduled launches, and remove local files at any time. Future weather/email features are not active integrations; this policy will need updating before introducing new data processing.

Contact and updates

For project privacy questions, contact the maintainer through GitHub issues or the contact options on OliW07's profile. Issues are public: use them only for non-sensitive questions or to request an appropriate private contact channel. Changes to this policy will be published here with an updated effective date.
