Privacy policy

Effective date: 26 November 2026.

Project and scope

Morning Brief is an independent personal desktop application maintained by the GitHub account OliW07. This policy covers this project's static website and the open-source desktop code in its repository. It does not replace Oura's, Google's, or GitHub's policies.

Oura data accessed

With your consent, the desktop application requests Oura's daily OAuth permission. It reads daily sleep, readiness and activity summaries and detailed sleep sessions. These may include scores, sleep times and stages, sleep efficiency, overnight heart-rate/HRV summaries, steps and activity energy. It does not request your email, personal-profile, or separate heart-rate time-series permissions.

Google and Gmail data accessed

Gmail is optional and requires your separate authorization. The Gmail integration requests only https://www.googleapis.com/auth/gmail.metadata. This scope permits access to mailbox labels and message metadata, but the current implementation requests only the INBOX label's unread-message and total-message counts. It does not request message lists, sender addresses, subjects, snippets, attachments or message bodies. It does not send, modify or delete email, and it does not request permission to do so.

The counts are used solely to show an unread-inbox summary in your personal morning briefing. OAuth access and refresh tokens and your own Google Desktop application's OAuth client configuration are used to authenticate these direct requests. The app does not request separate Google profile or contacts access.

Google API Services User Data Policy and Limited Use

Morning Brief's use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Google user data is used only to provide the user-facing inbox-summary feature you authorize. It is not sold, used for advertising, creditworthiness or lending decisions, or used to develop, train or improve generalized artificial-intelligence or machine-learning models. It is not provided to data brokers or project-operated analytics services. The maintainer does not receive or routinely access Google user data. Any access or transfer would be limited to what that policy permits, such as with your affirmative consent for a specific purpose, as necessary for security or applicable legal obligations; the current local implementation has no project-operated data-transfer backend.

Purpose and data flow

The app uses these records only to display your personal briefing, assess whether today's cloud data is available, and maintain a local cache for offline display. Requests go directly from your computer to Oura's authorization/token and API services over HTTPS. The OAuth callback listens temporarily on 127.0.0.1:8765, on your own computer, and is not a project-operated public server. Each installation registers its own Oura application.

Morning Brief retrieves records already available in Oura Cloud. It does not communicate directly with your ring. Oura's own collection and processing of those records are governed by Oura's policies.

For Gmail, your browser authorizes your own registered Google Desktop OAuth client. A temporary localhost callback returns authorization to the application on your computer. Token refreshes go directly to Google's OAuth service; inbox-count requests go directly to the Gmail API over HTTPS. Neither this website nor a project-operated server receives the authorization tokens or mailbox counts. Google's processing is governed by the Google Privacy Policy.

Weather and location

The weather feature sends your configured city's latitude and longitude to Open-Meteo, with MET Norway as a fallback. These providers receive the coordinates and normal network request information, such as your IP address. The app does not obtain GPS location or track your movements. No Oura records, Google credentials or Gmail counts are included in weather requests. Weather data is used only to display the local forecast and is cached on your computer.

Local storage and security

The desktop app stores OAuth access/refresh tokens, your API application's client ID and secret, cached Oura records, and daily trigger state on your computer. Default locations are ~/.config/morning-brief/ and ~/.local/state/morning-brief/; XDG settings may change these. Files created by its atomic storage helper are owner-readable/writable (0600). Tokens are not encrypted at rest; administrators, malware, backups, or other software with sufficient access may read them. Protect your computer and backups.

For Gmail, the default files are ~/.config/morning-brief/gmail-client.json, ~/.local/state/morning-brief/gmail-token.json, and ~/.local/state/morning-brief/gmail-cache.json. The cache contains inbox counts and refresh timestamps, not message contents. These files use the same owner-only storage protections and are not encrypted by the app. The originally downloaded OAuth client JSON may also remain wherever you saved it; it may be deleted after connection succeeds because the app keeps its private copy.

The code uses OAuth state verification, PKCE, serialized refresh-token rotation and HTTPS API calls. It does not log OAuth callback query strings. Local diagnostic logs can contain operational details; treat any shared logs as potentially sensitive. No security measure is a guarantee.

Sharing, analytics and advertising

The project does not operate a server that receives your Oura records, Gmail counts or account credentials. It does not sell personal data, include advertising, or include project-operated analytics or tracking SDKs. The desktop code contacts Oura, Google and the configured weather providers only for their respective features. No health information, mailbox data or account credentials should be submitted to this public website or repository.

This website and GitHub

This static website does not set application cookies, load third-party fonts, embed analytics, or provide a health-data collection form. It is hosted by GitHub Pages. GitHub may process visitor IP addresses and request information for hosting and security under the GitHub Privacy Statement. If you open an issue, GitHub processes your account and submitted content, and the issue is public. Do not post health records, tokens or secrets.

Retention and deletion

The app normally requests the most recent seven days and replaces its local successful-response cache on subsequent successful fetches. If fetching stops, the last cache remains until replaced or deleted. Tokens and setup state remain until you remove them; logs and backups may persist separately.

Gmail inbox counts are normally cached for five minutes before being refreshed on the next request. This is a freshness interval, not automatic deletion: the last cached counts remain until replaced or deleted, including when the network is unavailable. Weather forecasts are normally cached for thirty minutes. OAuth refresh tokens and client configuration remain until removed or revoked; providers may expire or revoke them earlier.

Disconnecting Gmail and deleting Google data

To revoke Gmail access, open your Google Account's third-party connections, select your Morning Brief connection and remove its access. Stop Morning Brief's automatic updates and running processes, then delete gmail-client.json, gmail-token.json and gmail-cache.json from the locations above to remove the app's local Google configuration, authorization and cached counts. Delete downloaded copies and backups separately if you want those removed too. Revocation does not itself erase a previously saved local cache; deleting files locally does not delete your Gmail messages or Google account.

You can revoke authorization through Oura's connected-application controls and stop the app's automation. To remove Morning Brief's local credentials and cached data, delete its configuration and state directories after stopping its processes. Deleting local files does not delete records from Oura's services. Contact Oura for account-level deletion or data-rights requests.

Your choices

Each integration is optional. You can use a clearly labelled sample preview without authorizing Oura or Google, connect Oura without Gmail, change or remove the configured weather city, revoke access, disable scheduled launches and remove local files at any time. The app will show missing or disconnected features without requiring broader permissions. Any future feature that accesses additional data will require appropriate consent and an updated policy.
